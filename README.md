# 水下考古连续潜次放行台

连续潜次的申报、放行判定与时间线管理。纯静态实现（ES Modules），无构建、无第三方依赖。

## 运行

直接用任意静态服务器打开根目录的 `index.html`（ES 模块需经 HTTP 访问）：

```bash
python3 -m http.server 8000
# 浏览器打开 http://127.0.0.1:8000
```

## 三个业务文件

| 文件 | 职责 |
| --- | --- |
| `src/rules.js` | **规则**：潜次排序、水面间隔判定、余量折减、放行状态、时间线筛选。纯函数，无存储、无 DOM。 |
| `src/records.js` | **记录**：申报 / 修订 / 补登出水、版本留档、幂等提交、全量重算、JSON/CSV 导出。存储可注入（浏览器默认 localStorage）。 |
| `src/pages.js` | **页面**：放行队列卡片、潜次时间线、修订留档、申报与修订表单、刷新与导出交互。 |

`index.html` 只是加载 `src/pages.js` 的薄壳与样式。

## 放行规则

1. **水面间隔**：相邻潜次（按下水时刻排序）水面间隔不足 **60 分钟**时，后一潜 `BLOCKED`，不得开始；恰好 60 分钟可放行。
2. **余量折减**：非首潜的可下水余量按**前一潜深度与时长**折减 **三成**（基线按本潜深度查表，连续潜次取 70%），判定结果中留痕前潜深度、时长、间隔与折减前后余量。
3. **待复核**：前一潜未登记出水时刻时，后一潜为 `PENDING_REVIEW`——只留待复核，**不能进入时间线**；补登出水后自动重算。
4. **修订重算**：修订任一潜次（或补登出水）后，所有后续潜次的放行状态与关联前潜标记按新值**全量重算**；旧版本进入留档，版本号递增。
5. **导出**：JSON / CSV 只含现行版本与当前判定，留档与幂等登记不进入导出。
6. **幂等**：每次提交携带令牌（页面自动生成），重复或并发的同令牌提交沿用首次受理结果；无令牌时按内容指纹去重。幂等登记持久化，**队列刷新后结果一致**。

状态：`CLEARED` 准予放行 · `BLOCKED` 间隔不足禁潜 · `PENDING_REVIEW` 待复核 · `INVALID` 数据异常。

## 测试

```bash
node --test        # 22 个用例：规则 10 + 记录 10 + 页面冒烟 2
```

- `test/rules.test.js`：间隔边界、折减、待复核、时间线排除、链式重算、排序。
- `test/records.test.js`：留档、级联重算、幂等（并发/刷新/失败重试）、导出排除旧版、CSV。
- `test/pages.smoke.test.js`：最小 DOM 桩挂载，验证渲染、刷新一致性与导出。

数据保存在浏览器 localStorage（键 `uwArchDiveStation.v1`），清除站点数据即可重置。
